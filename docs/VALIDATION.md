- ESP-IDF v5.3.3, commit `6db3dc25df7325c1c81b7cd7d4e42babff7a818e`.
- ESP32-S3 Xtensa GCC 13.2.0 (`esp-13.2.0_20240530`).
- CMake 3.24.3; Ninja 1.13.2; host GCC 13.3.0.
- Firmware source commit `3082ce37a9968cacb980c3950b53bcc06d47dc47`.
- Clean build: `IDF_COMPONENT_MANAGER=0 idf.py -B /workspace/scratch/catscan-clean-build build`.
  Target came from sdkconfig generated by `idf.py set-target esp32s3`.
- Host tests: `ASAN_OPTIONS=detect_leaks=0 IDF_PATH=/workspace/scratch/esp-idf ./tests/run.sh`.
- Extracted inline browser JavaScript: `node --check` PASS.
- `git diff --check`, including staged files: PASS.
- All product C components: `-Wall -Wextra -Werror`; host adds `-Wpedantic`.

The component manager was disabled because its process-tree inspection fails in
this container. CatScan has no managed external components, so all dependencies
still came from the actual IDF checkout. This environment setting is not needed
on a normal workstation. No IDF source was patched.

LeakSanitizer was unavailable because process inspection is restricted; ASan and
UBSan remained enabled. cppcheck was not installed; package installation failed
under the environment's permissions. Static analysis with cppcheck is therefore
NOT claimed. An earlier CMake 3.31 upstream deprecation warning was resolved by
using compatible CMake 3.24.3, not by suppressing project warnings.

## Coverage

- All six ranges: zero, positive full-scale boundary, negative full-scale,
  half-scale, and negative near-zero code; signed byte decoding.
- All four single-ended MUX settings and fixed rate/mode/comparator encoding.
- All 42 valid interval/gain combinations; every integer interval 0..11000.
- Wrong types, missing/duplicate/unknown keys, invalid gains, fractional values,
  out-of-range/overflow values, malformed number syntax, malformed/trailing JSON.
- State JSON round-trip, initial null values, ADC absent, I²C errors, stale boundary,
  config-change invalidation, CSV negative values, empty fields, short buffer.
- Simulated driver: initialization cleanup, NACK probe, channel switching,
  byte order, register readback mismatch, transport errors, bounded conversion
  waiting and recovery. These are mocks, not electrical timing measurements.

## Not validated on hardware

Actual pull-ups, breakout identity/supply compatibility, accuracy/noise/settling,
I²C waveforms, scan timing under network load, USB enumeration/reconnect and queue
behavior, Wi-Fi/HTTP integration, live browser rendering, stack margins, and
ADC disconnect/reconnect. Execute the checklist in HARDWARE.md before relying
on measurements. Host tests and a target build do not establish these properties.
